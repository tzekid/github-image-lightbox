# GitHub Image Lightbox

A tiny Safari Web Extension for github.com. Click a screenshot in an issue, PR,
comment or README and it opens in an overlay on the current page instead of a
new tab. Close it and you're exactly where you were.

Primary target: **Safari Technology Preview** on macOS. It works in regular Safari too.

| Interaction | Behavior |
|---|---|
| Click a screenshot that links to itself | Opens the overlay in the current tab |
| Escape, **Close**, or a click on the dimmed backdrop | Closes the overlay |
| Click (or drag) the image itself | Overlay stays open |
| ⌘/⌃/⇧/⌥-click, middle-click, right-click | Normal browser behavior |
| Focus the image link, press Enter | Opens the overlay; focus returns to the link on close |
| Image fails to load | "Couldn't load this preview." plus **Open original link** |

Badges, logos and other images that link somewhere *other* than the image keep
their normal link behavior.

The runtime is three files in [`extension/`](extension): `manifest.json`,
`content.js` and `content.css`. There is no build step, background worker,
popup, or privileged API, and nothing runs until you click.

## Use it in Safari Technology Preview (quickest)

Do all of this in Safari Technology Preview itself:

1. **Settings → Advanced** → enable **Show features for web developers**.
2. **Settings → Developer** → **Add Temporary Extension…**, authenticate, and pick
   this repo's `extension/` folder.
3. In **Settings → Extensions**, enable *GitHub Image Lightbox* and allow it on github.com.
4. After editing a file, reload the extension on the same Developer settings
   page, then refresh the GitHub tab.

Temporary extensions are removed when Safari quits or after 24 hours.

## Install it permanently

The `safari/` folder holds the macOS wrapper app generated by
`xcrun safari-web-extension-packager`. It references the files in `extension/`
directly, so there is still one copy of the code.

Build it signed with your own Apple Development team. A free Personal Team works.
Find your team ID in Xcode → Settings → Accounts.

```bash
xcodebuild -project "safari/GitHub Image Lightbox/GitHub Image Lightbox.xcodeproj" -scheme "GitHub Image Lightbox" -configuration Release -derivedDataPath safari/build DEVELOPMENT_TEAM=<YOUR_TEAM_ID> -allowProvisioningUpdates build
```

```bash
cp -R "safari/build/Build/Products/Release/GitHub Image Lightbox.app" ~/Applications/
```

```bash
open ~/Applications/"GitHub Image Lightbox.app"
```

Then enable it under **Settings → Extensions** in Safari Technology Preview
(and/or Safari) and allow it on github.com. A development-signed build stays
installed across restarts. An unsigned build ("Sign to Run Locally") needs
**Developer → Allow unsigned extensions**, which resets every time Safari quits.

To share it with other people, sign it with a Developer ID and notarize it
(that needs a paid developer account). The other route is to paste `content.js`
and `content.css` into the [Userscripts](https://github.com/quoid/userscripts)
extension.

## How images are detected

All GitHub-specific knowledge lives at the top of
[`extension/content.js`](extension/content.js). A click qualifies only when all of these hold:

- It is a plain primary-button click, not already handled, and not inside an
  editable control or the overlay itself.
- The nearest `<a href>` has no `download` attribute and is inside `.markdown-body`.
- That link contains exactly one `<img>` and no text.
- The link **demonstrably points at the same asset** as the image:
  - `a.href` equals `img.currentSrc` or `img.src`, or
  - it is a repository file: `href=/owner/repo/blob/<ref>/<path>` and
    `src=/owner/repo/raw/<ref>/<path>` on github.com.

Anything ambiguous is left alone. File extensions, CDN hostnames, image sizes and
`target="_blank"` are never used as evidence.

The overlay shows `img.currentSrc || img.src`, which is the exact URL GitHub
already rendered, signed query string included. Usually it comes straight from
the browser cache. **Open original link** is the untouched anchor `href`.

### Observed GitHub markup (October 2026)

Inspected on live pages in WebKit:

| Where | Container | Link → image |
|---|---|---|
| Uploaded attachment (issue/PR/comment) | `.markdown-body` (issues: `NewMarkdownViewer…`; PRs: `.comment-body`) | `href` **===** `src` = `https://private-user-images.githubusercontent.com/…png?jwt=…` |
| External image (Imgur, etc.) | `.markdown-body` | `href` **===** `src` = `https://camo.githubusercontent.com/<hmac>/<hex>`; `data-canonical-src` holds the real URL |
| Absolute raw URL | `.markdown-body` | `href` **===** `src` = `https://raw.githubusercontent.com/…` |
| Image committed to the repo | `.markdown-body.entry-content` | `href=/o/r/blob/<ref>/<path>`, `src=/o/r/raw/<ref>/<path>` |
| Animated GIF | `<animated-image>` inside `.markdown-body` | same as above; when its player is visible it has a second `a.AnimatedImagePlayer-images` with the same `href` |
| CI / shields badge | `.markdown-body` | `href` → Actions page / crates.io / etc. (**not** the image) |
| Logo linking to a website | `.markdown-body` | `href=https://astral.sh`, `src=raw.githubusercontent…` (**not** the image) |
| `<picture>` (light/dark variants) | `.markdown-body` | GitHub doesn't wrap these in a link, so they're out of scope |
| Avatars | outside `.markdown-body` | out of scope |

A badge with no explicit link gets auto-linked by GitHub to its own image. Those
*do* open in the overlay, which matches what GitHub itself does with them.

## Tests

End-to-end tests run Playwright's WebKit against **live github.com pages**. They
inject `extension/content.js` and `content.css` at document start, the way Safari
injects the declared content scripts.

```bash
npm install
```

```bash
npx playwright install webkit
```

```bash
npm test
```

## Limits

- It shows the image source GitHub selected for the page. That gives a larger
  viewing area, but it isn't necessarily the highest-resolution original.
- Signed `private-user-images` URLs expire after about five minutes. The overlay
  normally loads from the browser cache. If it can't, you get the error state and
  the original link, which behaves exactly like GitHub's own link.
- Only `https://github.com/*`. Gists, GitHub Enterprise and other hosts are out of scope.
